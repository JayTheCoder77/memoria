## What Memoria can do

Memoria is an **org-scoped agent memory layer**: write facts now or queue conversation for a worker, retrieve without calling a chat model, and optionally inject a compact user profile.

### Write

- **Immediate remember** — `POST /memories` or MCP `remember`. Dedup, embed, fan out KV + graph. Optional `user_id` / `agent_id` / `source_metadata`.
- **Async extract** — `POST /events` (`message`, `tool_call`, `diff`, `session_end`) or MCP `emit`. Worker groups by `(org_id, session_id)`, waits for the 120s window, batch size, or `session_end`, then one LLM extract per group (or heuristic).
- **Patch / delete** — update content (re-embeds), forget one or many; KV cascade; graph `memory_id` nulled.
- **Re-embed** — migrate rows from one stamped model to another (for example hash → minilm).
- **Extraction policy** — `GET`/`PUT /org/extraction-policy` (and dashboard settings when signed in). Extra instructions and an allow-list of categories.
- **Feedback** — `POST /memories/{id}/feedback` `{ "useful": true|false }`. One vote per API key: +0.1 / −0.2 on importance, clamped to `[0, 1]`.
- **Webhooks** — `POST /webhooks` for `memory.written`. Secret once; `X-Memoria-Signature` HMAC-SHA256. Payload has ids, not memory text. Delivery is after commit; receiver 500 does not fail the write.

### Read

- **Hybrid recall** — `GET /memories/search` (MCP `recall`): vector + Postgres FTS + KV + graph, fused with existing retrieval weights. Optional `session_id`, `user_id`, `agent_id`, `as_of`, `explain`, `metadata` containment, `rerank=true` if `MEMORIA_RERANKER=minilm` and the extra is installed.
- **List** — `GET /memories` with the same scope and metadata filters.
- **Profile** — `GET /profile?user_id=` (MCP `profile`): current KV facts plus up to five recent memories with `importance >= 0.6`, dropping dynamic lines that duplicate a static value; truncated to a token budget.
- **Indexes** — list/delete KV facts and graph edges.

### Ops and eval

- **Health** — `GET /health`.
- **Auth** — Google session for the dashboard; Bearer `mem_…` for API/MCP/SDKs.
- **Observability** — `X-Request-Id` (or generated), JSON `request_finished` logs, `/metrics` (`memoria_request_duration_seconds`, `memoria_llm_tokens_total`), `llm_usage` rows from chat completions.
- **Embedder policy** — `MEMORIA_EMBEDDER=hash` only when `MEMORIA_ENV=test`. Dev/prod default is MiniLM (`minilm` in-process extra, or `hf` Inference).
- **DolphinBench** — adapter `reset` / `ingest` (message + `session_end` + poll pending) / `freeze` / `context` (profile then search). Smoke script against a running API.

Clients: MCP (`remember`, `emit`, `recall`, `update`, `forget`, `profile` + optional scopes), `memoria-cloud-sdk`, `memoria-cloud-js`, `memoria-cloud-cli`.

### Known follow-ups from task reviews (not blockers)

These are logged in `.superpowers/sdd/progress.md`. Highest-impact if you harden after merge:

- Nested log fields and stdlib `logging` lines are not fully redacted; `/metrics` is unauthenticated.
- Dedup `similar()` can prefer a closer **other-scope** neighbor and skip a same-scope merge.
- Rerank `true` still runs retrieval before 400 when the reranker is not configured.
- Webhook DNS check and `httpx.post` are separate lookups (TOCTOU).
- Adapter `reset` does not delete `event_buffer` rows; failed event counts are cumulative.
- Several Postgres paths are covered mainly by in-memory store tests (scopes, KV history empty case, `delete_for_user`).
- Profile route does not map overlong `user_id` to 422.
- Extraction category strings split on commas; worker policy handoff is lightly tested.
- Settings extraction form was not browser-verified (Google sign-in).
